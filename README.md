# FastSignals

FastSignals is intended to become a Solana arbitrage intelligence and execution system with a Telegram interface. The current repository is an initial scaffold and must not be treated as production-ready arbitrage execution: price-only comparison is not enough for acceptance.

## What the bot does and does not do

- The bot **does not store private keys** and does not sign transactions.
- “1-click trading” means a Telegram button opens a prefilled Jupiter swap URL. The user still confirms the swap in Phantom/Solflare.
- Signals are generated by deterministic spread math, not by a neural network: compare prices across DEX venues, subtract fees/slippage/priority fee, run the security filter, then alert only if net spread is above threshold.
- For true arbitrage, SELL is not an optional later action: it is the second half of the `USDC → TOKEN → USDC` route and must be quoted before publication. Current Jupiter links are only a scaffold for non-custodial/manual UX.

See [`docs/TZ_PATCHNOTES.md`](docs/TZ_PATCHNOTES.md) and [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) for the revised ТЗ and target architecture. [`docs/TZ_CLARIFICATIONS.md`](docs/TZ_CLARIFICATIONS.md) explains the original disputed points.

## Features

- High-frequency async polling of Solana DEX pairs via DexScreener-compatible API.
- Security filter for mint authority, freeze authority, LP burned/locked percentage, and top holder concentration.
- Net-spread calculator for a configurable USDC order size.
- Telegram Settings UI from the ТЗ via admin-only commands for order size, minimum spread, liquidity/volume filters, pause, and resume.
- Multi-user subscriptions: `/start` subscribes a chat to signals, `/unsubscribe` removes it.
- SQLite persistence for settings, subscribers, and duplicate-signal suppression.
- Docker and Docker Compose deployment files for Ubuntu VPS.

## Target signal algorithm

1. Fetch live Solana market data from RPC/WebSocket/direct DEX integrations and use DexScreener/Birdeye only for discovery/enrichment.
2. Normalize quotes with timestamp, slot, source, pool, token mint, quote size, estimated output, price impact and quote age.
3. Reject stale quotes and candidates without both BUY and SELL routes.
4. Request executable quotes for the full `USDC → TOKEN → USDC` arbitrage route.
5. Evaluate dynamic order sizes and choose the optimal trade size by expected net P&L.
6. Run production-grade security scoring and risk checks.
7. Score the candidate deterministically and, after enough outcomes exist, with ML.
8. Publish only opportunities that remain executable after revalidation and exceed configured net profit thresholds.

## Environment

Copy `.env.example` to `.env` and fill in values:

```bash
cp .env.example .env
```

Required:

- `BOT_TOKEN`: Telegram bot token from BotFather.
- `ADMIN_IDS`: comma-separated Telegram user IDs allowed to manage global bot settings. Admins are also always included in signal delivery.

Optional defaults:

- `DEFAULT_ORDER_USDC=25`
- `DEFAULT_MIN_NET_SPREAD_PCT=0.8`
- `DEFAULT_MIN_LIQUIDITY_USD=5000`
- `DEFAULT_MIN_VOLUME_24H_USD=10000`
- `SLIPPAGE_PCT=0.5`
- `DEX_FEE_PCT=0.3`
- `PRIORITY_FEE_USDC=0.01`
- `POLL_INTERVAL_SECONDS=1.0`

## Local run

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e '.[dev]'
python -m fastsignals.bot
```

## Docker deployment

```bash
docker compose up -d --build
```

The compose file stores SQLite data in the named `fastsignals-data` volume.

## Telegram usage model

This is a multi-user bot. Any Telegram user who sends `/start` is added to the subscribers list and can receive signals. They cannot change global strategy settings unless their numeric Telegram user ID is listed in `ADMIN_IDS`. Users can remove only their own chat with `/unsubscribe`.

Admins are identified only by `message.from_user.id`, not by username. To add an admin, put their numeric Telegram ID into `ADMIN_IDS`, for example `ADMIN_IDS=111111111,222222222`, and restart the container.

## Telegram commands

User commands:

- `/start` — subscribe this chat to signals.
- `/unsubscribe` — unsubscribe this chat from signals.

Admin-only commands:

- `/settings` — show current runtime settings.
- `/set_order 25` — change test order size in USDC.
- `/set_spread 0.8` — change minimum net spread percent.
- `/set_liquidity 5000` — change minimum pool liquidity in USD.
- `/set_volume 10000` — change minimum 24h volume in USD.
- `/pause` — pause monitoring.
- `/resume` — resume monitoring.

## Signal format

Signals include token symbol, gross and net spread, estimated profit, security status, token mint, Jupiter buy button, Jupiter sell button, and DexScreener chart button. The bot never stores private keys; users confirm trades in their wallet after opening the Jupiter URL.
